The operational problem

A tree-care job passes through several people. The arborist’s scope, the sales agreement, the client’s confirmation, and the crew’s instructions need to stay aligned. Disconnected handoffs make it harder to tell which version of the work is approved.

My field and operations experience shaped the problem this capstone addresses: a shared work order with clear ownership at each step.

What changed in the latest build

The original browser prototype demonstrated the screens and workflow using browser storage. The updated local build introduces a Python server and a central SQLite database.

It checks permissions on the server, ties client confirmation to a version of the sales terms, and blocks scheduling until the current terms are confirmed.

01 / Service request02 / Scope & sales terms03 / Client confirmation04 / Office scheduling05 / Crew completion

Implemented & demonstrated

  • Login with hashed passwords and server sessions.
  • Role-based record access and CSRF protection.
  • Versioned client confirmation before scheduling.
  • Crew assignment restrictions and completion updates.
  • Central records and an append-only activity history.

Validation & next steps

All four existing automated tests passed on September 22, 2026. They cover unauthenticated access, incorrect passwords, CSRF enforcement, and role/approval rules.

Independent user acceptance testing, production hosting, centralized photo storage, and backup/restore validation remain future work. Fleet management, payments, and financial reporting are outside this capstone’s scope.
